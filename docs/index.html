Does Python have a switch statement?

Without

Yes — since Python 3.10, there's the match statement (structural pattern matching), which covers switch-style use and more:

def http_status(code):
    match code:
        case 200:
            return "OK"
        case 404:
            return "Not Found"
        case 500 | 502 | 503:
            return "Server Error"
        case _:
            return "Unknown"

Key points:

  • case _: is the default/fallback.
  • | combines alternatives.
  • No fall-through between cases, so no break needed.
  • It can also destructure data:
match point:
    case (0, 0):
        print("Origin")
    case (x, 0):
        print(f"On x-axis at {x}")
    case {"type": "circle", "radius": r}:
        print(f"Circle with radius {r}")
    case Point(x=x, y=y) if x == y:
        print("On the diagonal")

Gotcha: a bare name in a case is a capture pattern, not a comparison. case RED: matches anything and binds it to RED. To compare against a constant, use a dotted name like case Color.RED:.

Before 3.10, the usual alternatives were if/elif chains or a dict lookup:

handlers = {"add": add, "sub": sub}
result = handlers.get(op, default_handler)(a, b)

How do I undo my last git commit but keep the changes?

Without

Use a soft reset:

git reset --soft HEAD~1

This removes the last commit but keeps its changes staged, ready to recommit.

Variants:

  • git reset HEAD~1 (same as --mixed): undoes the commit and keeps the changes, but unstaged.
  • git reset --hard HEAD~1: discards the changes entirely. Avoid this if you want to keep your work.

If you already pushed the commit, resetting rewrites history, and you'd need to force-push (git push --force-with-lease). On shared branches, git revert HEAD is usually safer. It creates a new commit that undoes the last one without rewriting history, though it doesn't leave the changes in your working tree.

If you just want to fix the commit (message or contents), git commit --amend is often simpler than resetting.

How do I delete all Docker containers, images and volumes to free up disk space?

Without

Here's how to wipe Docker's disk usage. All of these are destructive and irreversible — volumes especially may hold database data you can't recover.

Check what's using space first

docker system df        # summary
docker system df -v     # per-image/container/volume detail

The one-liner (nuclear option)

docker system prune -a --volumes

This removes:

  • all stopped containers
  • all images not used by a running container (-a; without it, only dangling images)
  • all unused networks
  • all unused volumes (--volumes)
  • all build cache

Add -f to skip the confirmation prompt.

Note: it won't touch anything in use by running containers. To truly delete everything, stop and remove those first:

docker stop $(docker ps -q)
docker rm -f $(docker ps -aq)
docker system prune -a --volumes -f

Piece by piece (if you want more control)

docker container prune          # stopped containers
docker image prune -a           # unused images
docker volume prune -a          # unused volumes (-a includes named volumes, Docker 23+)
docker builder prune -a         # build cache — often the biggest hog
docker network prune            # unused networks

macOS-specific tip

On Docker Desktop, all of this lives in a single VM disk image that doesn't always shrink automatically after pruning. If Finder still shows the space as used:

  • Docker Desktop → Settings → Resources → Advanced → lower the "Virtual disk limit", or
  • Troubleshoot (bug icon) → Clean / Purge data — resets everything and reclaims the full disk image.

If you want, I can run docker system df for you to see where the space is going before you delete anything.

Heeft Python een switch-statement?

Without

Ja, sinds Python 3.10 heeft Python het match-statement (structural pattern matching, PEP 634). Het lijkt op een switch, maar kan meer:

def http_status(code):
    match code:
        case 200:
            return "OK"
        case 404:
            return "Not Found"
        case 500 | 502 | 503:          # meerdere waarden
            return "Server error"
        case _:                         # default
            return "Onbekend"

Verschillen met een klassieke switch:

  • Geen break nodig: er is geen fall-through, alleen de eerste passende case wordt uitgevoerd.
  • _ is de wildcard (de default).
  • Je kunt op structuur matchen, niet alleen op waarden:
match punt:
    case (0, 0):
        print("Oorsprong")
    case (x, 0):
        print(f"Op de x-as, x={x}")
    case (x, y) if x == y:            # guard
        print("Op de diagonaal")
    case {"type": "cirkel", "r": r}:   # dicts
        print(f"Cirkel met straal {r}")
    case Punt(x=0, y=y):               # objecten/dataclasses
        print(f"Op de y-as, y={y}")

Let op: een losse naam in een case is een capture, geen vergelijking. case STATUS_OK: matcht dus alles en kent de waarde toe aan STATUS_OK. Gebruik een gestippelde naam (case Status.OK:) of een letterlijke waarde om te vergelijken.

Vóór 3.10 gebruikte je meestal if/elif/else of een dictionary:

acties = {"start": start, "stop": stop}
acties.get(commando, onbekend)()

Hoe maak ik mijn laatste git-commit ongedaan maar houd ik de wijzigingen?

Without

Gebruik git reset met --soft of --mixed:

git reset --soft HEAD~1

De commit verdwijnt, maar je wijzigingen blijven gestaged (klaar om opnieuw te committen).

git reset HEAD~1        # zelfde als --mixed

De commit verdwijnt, je wijzigingen blijven in je werkmap maar zijn niet gestaged.

Let op:

  • Gebruik niet --hard, want dan ben je de wijzigingen kwijt.
  • Is de commit al gepusht? Dan herschrijf je met reset de geschiedenis en moet je force-pushen (git push --force-with-lease). Op een gedeelde branch is git revert HEAD veiliger. Dat maakt een nieuwe commit die de vorige ongedaan maakt.
  • Wil je alleen het commitbericht of de inhoud aanpassen? Dan volstaat git commit --amend.

Hoe verwijder ik alle Docker-containers, images en volumes om schijfruimte vrij te maken?

Without

Je kunt dit het beste stap voor stap doen. Bekijk eerst wat er ruimte inneemt en voer daarna pas de opruimcommando's uit.

1. Kijk wat er ruimte inneemt

docker system df

Voor meer detail per image, container en volume:

docker system df -v

2. Alles in één keer opruimen

docker system prune -a --volumes

Dit verwijdert:

  • alle gestopte containers
  • alle ongebruikte images (-a: ook images met een tag, niet alleen "dangling")
  • alle ongebruikte netwerken
  • alle ongebruikte volumes (--volumes)
  • de build cache

Docker vraagt om bevestiging. Met -f sla je die vraag over.

3. Ook draaiende containers verwijderen (echt alles)

prune laat draaiende containers en hun images en volumes staan. Wil je een volledig schone lei:

docker stop $(docker ps -q)            # stop alle draaiende containers
docker rm -f $(docker ps -aq)          # verwijder alle containers
docker rmi -f $(docker images -aq)     # verwijder alle images
docker volume rm $(docker volume ls -q) # verwijder alle volumes
docker builder prune -a -f             # verwijder de build cache

Per onderdeel (selectiever)

docker container prune    # gestopte containers
docker image prune -a     # ongebruikte images
docker volume prune -a    # ongebruikte volumes (-a ook voor named volumes, Docker ≥ 23)
docker builder prune -a   # build cache

⚠️ Let op

  • Volumes bevatten vaak data, zoals databases van lokale dev-omgevingen. Na verwijderen is die data weg. Controleer eerst met docker volume ls of je iets wilt bewaren.
  • Docker Desktop op macOS: de schijfruimte zit in een virtuele disk (Docker.raw). Die krimpt niet altijd meteen. Zie je geen verschil, gebruik dan in Docker Desktop Troubleshoot → Clean / Purge data, of verklein de disk limit onder Settings → Resources.

Zal ik eerst docker system df voor je uitvoeren, zodat je ziet hoeveel er vrij te maken valt?
